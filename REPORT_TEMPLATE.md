# SWD 414 Assignment Report
## Title: Managing a Web Development Project Using Git and GitHub

### 1. Introduction
This project demonstrates how Git and GitHub can be used to manage a small website for the Department of Computing. The website contains a homepage, About Us page, Programmes page and Contact Us page.

### 2. Project setup
I created a project folder and developed the website using HTML and CSS. I created the following files: `index.html`, `about.html`, `programmes.html`, `contact.html` and `style.css`. I initialized Git in the project folder with `git init` and checked the working tree using `git status`.

### 3. Recording changes
I staged the initial website files with `git add .` and saved them using a commit. I then improved the homepage and saved that update in another commit. I used `git log --oneline` to view the project history and identify the recorded commits.

### 4. Working with branches
I created a separate branch named `contact-page` to work on the Contact Us page. After completing the page, I committed the changes, switched back to the main branch and merged the branch. This kept the work organized and demonstrated how a feature branch can be integrated into the main project.

### 5. Using GitHub
I created a new remote repository on GitHub, connected it to my local repository and pushed the project. The remote repository contains the website files and commit history.

### 6. Updating the project
After the first push, I made another change, committed it locally and pushed it to GitHub.

**Difference between commit and push:** A commit saves a snapshot of changes in the local Git repository. A push uploads local commits to a remote repository such as GitHub so that they are available online and can be shared with other collaborators.

### 7. Challenges encountered
Possible challenges included learning the correct Git commands, resolving branch or merge issues, and connecting the local repository to GitHub. These can be addressed by checking `git status`, reading Git error messages carefully, and confirming that the correct remote URL is configured.

### 8. Conclusion
The project demonstrates basic version-control practices: initializing a repository, tracking files, committing changes, creating and merging a branch, and pushing work to GitHub.
